# Fieldguide 界面与交互规格

> 版本：v0.6 | 状态：设计修订（理解工作台分屏；VS Code 风格布局，**默认不与外部笔记应用耦合，唯一例外是用户显式绑定的 Obsidian vault（F-17）**）  
> v0.6 变更：新增 `vault` 面板与「设置 → Obsidian」分类（F-17 Obsidian vault 联动；单向导出，非双向同步）（2026-09-20）  
> v0.5 变更：面板目录扩展为 overview / graph / code / chat / tour / knowledge / interview；布局预设  
> v0.4 变更：三栏布局 → 左文件树 + 右可分隔面板（2026-07-01）

---

## 一、设计目标

参考 **VS Code** 的开发者工作台体验：左侧项目文件树导航，右侧可自由分隔为 1~2 个面板，每个面板可在**有限面板类型**间切换。

**代码地图核心能力**：由 **[Understand-Anything Dashboard](https://github.com/Egonex-AI/Understand-Anything)**（iframe 嵌入）提供图谱交互；Fieldguide 负责文件树、代码阅读器、问答、Tour、架构总览、知识、面试，以及面板间联动。

详见 [understand-anything-integration.md](./understand-anything-integration.md) §4.3。

│  状态栏：索引状态 · 节点数 · 当前项目名 · 面板布局指示                        │ ← 24px
└──────────────────────────────────────────────────────────────────────────┘
```

**布局规则**：
- **左侧文件树**：宽度 260px（默认），可拖拽调整 160px–400px，可一键折叠
- **右侧面板区**：flex-1，内部可拖拽分隔为 1 或 2 个面板（左右或上下排列）
- **面板 Tab（V1 固定目录）**：`overview` | `graph` | `code` | `chat` | `tour` | `knowledge` | `interview` | `vault`（Tab 栏可横向滚动）
- **默认布局**：单面板显示图谱；用户可拖拽分出第二个面板
- **布局预设**：总览|图谱、知识|代码、面试|问答、导览|代码、**Vault|代码**
- **面板最小宽度**：280px
- **旧布局迁移**：升级后自动补全新 Tab，保留用户 activeTab / 分屏比例
- **Vault Tab 自动出现（F-17）**：Tab 列表每次加载都由面板目录 `ALL_PANEL_TABS` 重建（`migratePanelTabs` 不读旧值），所以老用户无需迁移配置、也不用手动添加，Tab 栏里就会多出 `vault`
- **刻意不做**：把知识产物交给外部笔记应用**托管**——知识与问题产物始终保存在本机 Fieldguide 数据中；耦合仅限用户在「设置 → Obsidian」**显式绑定**的**一个** vault 目录（F-17，单向导出，见 §3.2.7 / §3.5）

### 2.3 顶栏

- **Logo + 产品名**：点击回到项目库
- **主导航 Tab**：项目库 | 代码地图 | 理论 | 桥接（当前 Tab 下划线高亮）
- **面板布局控制**（代码地图 Tab 内）：单面板 / 左右双面板 / 上下双面板 / 交换 / **预设菜单**
- **全局搜索（Ctrl+K）**：命令面板（重新索引、切换项目、打开设置）；代码语义搜索由 LLM 问答面板负责
- **设置**：API Key、语言、主题、关于

**规则**：未选中项目时，「代码地图 / 桥接」Tab 禁用并 tooltip「请先添加项目」。

## 三、视图规格

### 3.1 项目库

**空状态**（居中）：
- 插图 + 「添加你的第一个项目」
- 主按钮：「选择本地文件夹」
- 次按钮：「从 Git URL 克隆」

**列表项**（卡片或表格）：
- 项目名、主语言 badge、框架 tag
- 索引状态：就绪 / 索引中（进度环）/ 失败（可重试）/ **源码已变更**（橙色小圆点 + tooltip）
- 元信息：节点数、最后索引时间、`root_path` 摘要（hover 显示完整路径）
- 操作：打开地图 · 重新索引 · 删除

**添加 Git 对话框**：
- URL 输入、分支（可选）、浅克隆 checkbox
- **目标目录**：默认 `{projectsRoot}/{slug}/`
- 若未设置 `projectsRoot`：每次必须选择目录

### 3.2 代码地图（核心 — v0.4 重写）

> **实现来源**：图谱由 **UA Dashboard** iframe 嵌入提供；文件树、代码阅读、LLM 问答由 Fieldguide 自建。详见 [understand-anything-integration.md](./understand-anything-integration.md) §4.3。

#### 3.2.1 左侧：项目文件树

| 特性 | 说明 |
|------|------|
| **数据来源** | `scan-project.mjs` 扫描结果或直接读取项目目录 |
| **展示方式** | VSCode 风格树形目录，可折叠/展开 |
| **文件图标** | 按语言/文件类型显示图标（Lucide 图标 + FileIcon 组件，~15 种文件类型区分色） |
| **点击行为** | 在右侧「代码」面板打开文件 |
| **右键菜单** | 在资源管理器打开、复制路径 |
| **搜索过滤** | 文件树顶部内联搜索框（输入即过滤） |
| **索引状态叠加** | 已索引文件旁显示小绿点；未索引/新增文件灰点 |

**快捷键**：`Ctrl+Shift+E` 聚焦文件树。

#### 3.2.2 右侧：可分隔面板

**面板类型**（每个面板顶部 Tab 切换）：

| Tab | 名称 | 内容 | 实现来源 |
|-----|------|------|----------|
| 图谱 | Graph | UA Dashboard iframe 嵌入（交互式知识图谱） | UA Dashboard |
| 代码 | Code | Monaco Editor 或简单语法高亮文本区 | Fieldguide（只读预览） |
| 问答 | Chat | LLM 对话，上下文绑定当前项目/文件/节点 | Fieldguide |

**面板操作**：
- **添加面板**：点击面板区右上角 `[＋]` 或拖拽现有面板边缘分离
- **关闭面板**：面板 Tab 栏右侧 `[×]`，最后一个面板不可关闭
- **切换布局**：顶栏按钮切换左右/上下排列
- **拖拽分隔条**：调整两个面板的比例（50/50 默认，限制 20/80 ~ 80/20）
- **面板最大化**：双击面板 Tab 或 `Ctrl+Shift+M`，再次执行恢复

**默认布局**（打开项目时）：
- 右侧为**单面板**，默认显示「图谱」Tab
- 在文件树点击文件 → 仅更新活动面板的 filePath，不自动分屏（对齐 Obsidian 单文件打开行为）
- **双面板默认**：左 = 代码，右 = 图谱（可通过布局按钮交换）

**面板联动**（Phase 2）：
- 图谱中点击节点 → 代码面板跳转到对应文件:行号
- 代码面板选中符号 → 图谱高亮对应节点
- 问答面板引用节点 → 图谱/代码面板跟随

#### 3.2.3 图谱面板（UA Dashboard iframe）

**Fieldguide 职责**：

#### 3.2.7 Vault 面板（Fieldguide 自建，F-17）

> 项目拆解产物在 Obsidian vault 里的那一面：同步了什么、哪张卡需要你决定、你自己写了多少。**只有这个面板展示卡片状态**——状态是「我们写的 / 磁盘上的 / 现在的来源」三方比较的结果。

**布局**：左侧卡片列表（固定 ~42% 宽），右侧选中卡片的预览；dry-run 计划展开时横跨整个面板顶端。

| 特性 | 说明 |
|------|------|
| **面板头** | 标题 + `vault 名 · 项目目录`；右侧「同步到 vault」按钮、同步过之后多一个「在 Obsidian 打开索引」 |
| **卡片列表** | 列表头显示「N 张卡片」与「仅看问题（N）」开关；每行：标题 + `kind` 标签 + 状态标签，有你的批注时追加「你写了 N 字」 |
| **状态标签** | `已同步`（与上次写入一致）/ `你已修改`（生成块之外有你自己的批注，可安全再同步）/ `需要处理`（托管块标记被删、或该路径上的文件本来就不是 Fieldguide 写的——此时不再知道哪部分属于自己，于是原样保留）/ `文件缺失`（记账行在、文件不在）；后两者用错误色，`你已修改` 用强调色 |
| **过滤** | 「仅看问题（N）」一键只看 `需要处理` / `文件缺失` |
| **预览** | 右侧顶部显示笔记路径 + 「打开」「采纳为代码笔记」；正文渲染 Markdown（wikilink 显示为标签文本）；底部是「清理生成的卡片」与上次同步时间 |
| **同步** | 「同步到 vault」先出 **dry-run 计划**（新建 / 更新 / 未变 / 冲突 / 删除计数 + 最多 5 条冲突路径），确认后才写入；写入的就是预览过的计划 |
| **冲突处理** | 选中 `需要处理` / `文件缺失` 的卡片时，预览上方出现三选一：`保留我的版本`（把磁盘版登记为新基线）/ `用 Fieldguide 版本覆盖`（只重写托管块）/ `另存为副本`（两边都不丢） |
| **清理** | 「清理生成的卡片」二次确认后删除 Fieldguide 生成的文件，**改过的笔记保留**并回报「删除 N 个 / 保留 M 个」 |
| **空态与门禁** | 未绑定 vault：指向「设置 → Obsidian」并给绑定步骤；有绑定但没同步过：提示先索引项目、再回这里同步；CLI 未运行时顶部提示「同步仍可用（直接写文件），只有在 Obsidian 打开需要它运行」 |

### 3.5 设置

| 分组 | 项 |
|------|-----|
| LLM | Base URL、API Key（密码框）、Chat Model、Embed Model、测试连接 |
| 通用 | **界面语言**（简体中文 / 繁體中文 / English (US)，即时切换）、主题（系统/浅/深） |
| 项目 | **项目根目录**（Git clone 与 Demo 默认父路径） |
| 索引 | 默认忽略规则、并行度、浅克隆默认 |
| Obsidian（F-17） | CLI 状态与修复指引、手动 CLI 路径、vault 绑定/新建/已有库列表、同步选项（详见下） |
| 数据 | 打开数据目录、清除缓存、导出图谱 |
| 关于 | 版本、文档链接 |

**「Obsidian」分类（F-17）**：

- **CLI 状态**：状态药丸显示 `可用` / `未检测到 CLI` / `Obsidian 未运行` / `Obsidian 版本过低`（另有 `CLI 调用失败`），旁边是「重新检测」与「启动 Obsidian」（先试 CLI 同级的 GUI 二进制，再试 `obsidian://`）；探测结果有短缓存，设置页轮询不会反复 spawn
- **修复指引**（未可用时展开）：① 升级到 1.12.7 或以上的**安装器**版本；② Obsidian 里「设置 → 通用」启用「命令行界面（Command line interface）」并按提示完成注册；③ 重启终端（PATH 变更需要新的终端会话）；④ 确认 Obsidian 正在运行后点「重新检测」；仍失败可展开诊断信息
- **手动 CLI 路径**：输入框 + **文件选择器**覆盖自动探测（留空 = 自动检测），失焦即重探
- **vault**：「选择目录」（系统目录选择器 + 路径校验）、「新建 vault」（父目录 + 名称；只建目录与空 `.obsidian/` 标记）、「打开库管理器」（`obsidian://choose-vault`）；下方是**已识别的 vault 列表**，可一键切回
- **硬门禁**：CLI 不可用时「选择目录」「新建 vault」置灰，并说明「需要先有可用的 Obsidian CLI」，不给半可用状态
- **登记引导**：当前绑定显示类型徽标（`已在 Obsidian 中识别` / 未登记 / 嵌套在别的库里）。未登记时提示在库管理器里「打开文件夹作为库」并选择该路径，之后轮询 `obsidian vaults`，登记成功自动确认；超时则提示稍后「重新检测」
- **同步选项**：vault 内目录名（默认 `Fieldguide`）、索引完成后自动同步、把我的代码笔记镜像到 vault、允许问答 Agent 写入卡片、同步后在 Obsidian 打开索引；改动需点左下角「保存」生效，换绑 vault 不会自动删除旧目录里已生成的卡片（面板里有清理入口）

## 四、组件规范

### 4.1 文件树

- 使用虚拟滚动（大量文件时不卡）
- 目录箭头：▸ 折叠 / ▾ 展开
- 缩进：每层 16px
- 选中项高亮：VSCode 风格（`#E4E6F1` 浅色 / `#2A2D3E` 深色）
- 字体：`Segoe UI` 13px

### 4.2 可分隔面板

- 分隔条：4px 宽，hover 时变色（`#3B82F6`），cursor: col-resize / row-resize
- 面板 Tab 栏：高度 32px，Tab 宽度自适应，活跃 Tab 底部蓝色下划线
- 面板最小宽度：280px

### 4.3 Tab 切换动效

| 场景 | 动效 | 时长 |
|------|------|------|
| 面板 Tab 切换 | 内容区淡入 | 100ms |
| 面板添加/关闭 | 宽度过渡 | 200ms |

### 4.4 ThoughtChain（思考链）

LLM 问答面板中，每步 ReAct 可折叠：

```

## 五、视觉规范

### 5.1 主题

**主题预设**（5 套可选，默认 `parchment`）

| 预设 | 类型 | 说明 |
|------|------|------|
| parchment (默认) | 浅色 | 米白纯色底 `#FDFCF8`，白卡片，鼠尾草绿强调 `#4A8B71`，现代笔记本质感 |
| forest | 深色 | 深绿底色 `#1B2E1E`，草木绿强调 `#7DBF6E` |
| slate | 浅色 | 蓝灰底 `#F0F2F5`，紫罗兰强调 `#6366F1` |
| midnight | 深色 | GitHub Dark 风格 `#0D1117`，天蓝强调 `#79C0FF` |
| paper-dark | 深色 | 暖暗底 `#2D2420`，金棕强调 `#D4A76A` |
| none | — | 无预设，跟随系统亮/暗默认值 |

**parchment 默认色值**（v2 · 对齐 sampleTheme.png）：

| 令牌 | 值 |
|------|-----|
| `--fg-bg` | `#FDFCF8` |
| `--fg-card` | `#FFFFFF` |
| `--fg-border` | `#E0E0E0` |
| `--fg-text-primary` | `#222222` |
| `--fg-text-secondary` | `#757575` |
| `--fg-accent` | `#4A8B71` |
| `--fg-accent-muted` | `#EBF4F0` |
| `--fg-sidebar-bg` | `#F8F7F4` |

**parchment 背景**：纯色米白 `#FDFCF8`（无网格纹理）；侧栏 `#F8F7F4`。

**主题系统**：所有颜色通过 CSS 语义令牌 `--fg-*` 定义（`tokens.css`），组件禁止使用硬编码 Tailwind 颜色类。覆盖顺序：`:root` 默认 → `[data-theme="dark"]` → `[data-theme-preset="..."]`。

**浅色（none 预设 / 无预设）**：
- 背景 `#FAFAFA`，卡片 `#FFFFFF`，边框 `#E5E7EB`
- 文字 primary `#111827` / secondary `#6B7280`
- 文件树选中 `#E4E6F1`

**深色**：
- 背景 `#0F172A`，卡片 `#1E293B`，边框 `#334155`
- 文字 primary `#F8FAFC` / secondary `#94A3B8`
- 文件树选中 `#2A2D3E`

### 5.2 字体

- UI：`Segoe UI`, system-ui, sans-serif
- 代码：`Cascadia Code`, `Consolas`, monospace
- 字号：正文 14px，标题 16–20px，代码 13px，文件树 13px
