# FieldGuide 项目改造指导文档

## 文档用途

本文件用于指导 AI Agent 参与 FieldGuide 项目的架构设计、功能规划和迭代。

------------------------------------------------------------------------

# 一、重新定位

FieldGuide 不应该只是：

「AI代码解释工具」

市场已有大量类似产品。

建议定位：

> AI时代的软件理解系统。

核心问题：

当 AI 生成大量代码后，开发者如何快速理解、维护和评估？

------------------------------------------------------------------------

# 二、核心能力设计

## Capability 1: Architecture Mapping

目标：

将代码仓库转换为软件架构地图。

输入：

Github Repository / Local Project

输出：

    System Overview

    Frontend
     |
    API Layer
     |
    Business Logic
     |
    Data Layer
     |
    External Services

展示：

-   模块关系
-   数据流
-   关键依赖
-   技术选型

------------------------------------------------------------------------

## Capability 2: Knowledge Extraction

这是 FieldGuide 与个人知识库连接的关键。

分析项目后自动发现技术点，并在 **FieldGuide 应用内**生成知识节点（不依赖 Obsidian 或其他外部 PKB）：

例如：

    Redis
    Kafka
    Golang Worker Pool
    Docker
    Kubernetes

生成：

知识节点：

    为什么使用Redis？
    Kafka解决什么问题？
    Worker Pool如何设计？

用户通过分屏「知识 | 代码」在应用内对照阅读。

------------------------------------------------------------------------

## Capability 3: Interview Simulation

针对项目生成：

    可能面试问题：

    为什么这样设计？
    如果流量增加怎么办？
    这里有什么风险？
    为什么不用其他方案？

目标：

把项目理解转化为面试能力。

------------------------------------------------------------------------

# 三、应用内理解闭环

理想架构：

    项目代码
      ↓
    FieldGuide分析
      ↓
    产生技术问题
      ↓
    生成Knowledge Node（应用内）
      ↓
    分屏对照代码 / 图谱
      ↓
    形成理解
      ↓
    面试演练面板反向巩固

> 产品保持独立：不与 Obsidian 等外部工具耦合。

------------------------------------------------------------------------

# 四、Agent开发原则

## 不追求一次生成完整报告

采用渐进式：

第一阶段：

-   项目结构解析

第二阶段：

-   架构理解

第三阶段：

-   技术知识抽取

第四阶段：

-   面试模拟

------------------------------------------------------------------------

# 五、推荐核心数据模型

Project:

    name
    stack
    architecture
    modules
    dependencies
    questions
    knowledge_links

Question:

    problem
    context
    answer
    related_concepts

Knowledge:

    concept
    principle
    tradeoffs
    examples

------------------------------------------------------------------------

# 六、未来扩展方向

## AI代码审查

分析：

-   潜在Bug
-   架构风险
-   技术债

## AI导师模式

基于项目上下文：

主动提问：

"你知道为什么这里不用XXX吗？"

## 学习路径生成

根据目标岗位：

自动规划：

项目经验 -\> 知识缺口 -\> 学习路线

------------------------------------------------------------------------

# 七、最终愿景

FieldGuide不是帮助用户生成代码。

而是帮助用户：

理解AI生成的软件。

在AI时代，人类工程师的核心竞争力：

不是打字速度。

而是：

理解、判断、设计能力。
