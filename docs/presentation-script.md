# 答辩演示脚本与常见追问

> 两套脚本：**无 Key**（任何机器都能跑，保险）与**有 Key**（效果更好）。
> 演示前先跑一次 `pnpm build`；数据目录用临时目录（`FIELDGUIDE_DATA_DIR`）以免污染本机。

## 二、12 分钟演示（有 Key 版：把问答与论文对照加进来）

## 三、高频追问与答法

**Q1 图谱引擎是别人的，你做了什么？**
贡献边界表（见 `docs/项目介绍.md` §1）：上游只做解析与画布，本项目做问答、检索改进、学习闭环、
所有权模型、任务中心、评测体系与全部工程质量。举两个只有集成层能做的例子：
检索改进（上游没有中文分词与术语映射）、Obsidian 所有权模型（上游没有导出能力）。

**Q2 为什么不用 LangChain / LlamaIndex？**
桌面本地单用户、工具集固定 13 个、需要精确控制上下文预算与重试语义。自有的 300 行循环换来
可消融、可单测、可观测（token 计量、失败率、重试次数）。框架会把这些变成黑盒。

**Q3 68% / 42.9% 的召回是不是太低？**
那是**离线检索层**的召回（不含模型阅读），作为下界；产品里靠上下文打包 + 模型阅读弥补。
更要紧的是口径：命中 = 节点 id 或所在文件命中标注，且标注非穷举（只标"真正能回答"的），
所以绝对值被系统性压低，只能做**变体间相对比较**。

**Q4 为什么邻居扩展没有收益还留着？**
如实说：在 pulsegate 上零增益（语义检索已召回同文件多节点），在 tiny-go 上有 +8.3pp。
它的价值是给模型提供连接关系（答案级收益），检索召回指标测不到——这一点已经写进报告。

**Q5 为什么向量检索用暴力余弦？**
单机论文规模够用、零额外依赖、结果完全可解释；无 ANN 是已知局限，写进未来工作。

**Q6 怎么保证不写坏用户的笔记？**
四条性质 + 随机化属性测试（80 个随机世界，覆盖 create/update/skip/adopt/conflict/orphan-kept/delete
七类决策）：幂等、最小改写、用户内容永不被删、路径封闭。

**Q7 索引失败了会怎样？**
不会全盘失败：结构图照常保存，任务中心显示"部分完成（摘要阶段失败，结构与图谱已保存）"，
并提供一键重试（用上次的模式）。这是产品非功能需求"失败保留部分结果"的落地。

**Q8 停止生成之后半截回答去哪了？**
用户的问题保留（他确实问了），半截回答**不写入历史**（避免留下不完整结论），并且**不重试**
——一旦文字已经流到读者眼前，重试会把已看过的内容再说一遍。

**Q9 为什么不用内容哈希做增量？**
当前是 mtime 水位线 + 在场集合，代价是"内容改回旧值会无必要重解析""时钟回拨会漏改"；
换内容哈希是明确的改进项，已写进局限。

**Q10 用户研究做了吗？**
没有。协议、SUS 量表、计分与统计代码齐备（含无效问卷剔除与 95% CI），
但仓库里**不预置任何模拟结果**——数据必须由真实参与者产生。

## 四、局限页（建议做成 PPT 最后一页）

1. `sandbox: false`：安全模型是进程隔离 + 最小暴露面，不是 Chromium 沙箱；
2. IPC 无运行时 schema 库，一致性靠 5 组静态契约审计；
3. 中文检索仍弱于英文/关键词，术语映射 73 条且人工维护；
4. 原子写无 `fsync`；并发保护只在进程内；
5. 增量用 mtime 水位线，文件改名会静默断掉跨文件边；
6. 论文向量检索无 ANN，全表 + JS 余弦；
7. embedding 未计入 token 计量（成本只覆盖对话侧）；
8. 覆盖率有意图无门禁；
9. `qa:his-go` 依赖外部仓库；E2E 未进 CI；
10. 真人用户研究待执行。
