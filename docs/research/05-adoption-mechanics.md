# Adoption mechanics for developer tools — evidence review

**Scope:** what actually makes developer tools spread, with concrete cases, numbers, and working citations — commissioned because Fieldguide is being judged "too single-feature / too ordinary."

**Method.** Searches via web search, then real page fetches with PowerShell (`Invoke-WebRequest`). Live APIs used for neutral numbers: GitHub repo pages (star counter; the GitHub REST API was rate-limited to 0 on this network), `api.npmjs.org/downloads/point`, `formulae.brew.sh/api/formula/*.json`, the VS Code Marketplace `extensionquery` endpoint, `hub.docker.com/v2/repositories/`, and the HN Algolia API. Every cited URL was checked for HTTP 200 (a few sites return 405 to `HEAD` or 403 to bots; those are flagged inline and a primary substitute was used). Research conducted late September 2026, which is why some sources are 2026-dated.

**How to read the labels.** `[audited]` = a number we pulled from an API, registry, or marketplace that the vendor does not control (stars, npm/weekly downloads, Homebrew installs, Marketplace install counts, HN points, Docker pulls, wire-service funding reports). `[self-reported]` = a vendor's own ARR, user, growth, or conversion claim, usually unaudited and often published alongside a fundraising round. **Most growth claims in this space are marketing.** Where we found nothing, we say `UNVERIFIED` rather than estimating.

## 1. Shareable artifacts / viral output

**Mechanism:** the tool's *output* is a public artifact that carries a link back, so every user's work markets the product.

**Cases:**

- **DeepWiki** — `deepwiki.com/OWNER/REPO` is a public wiki page per GitHub repo; Cognition pre-indexed top public repos so the landing surface is *other people's repos*, not its own marketing ([cognition.ai/blog/deepwiki](https://cognition.ai/blog/deepwiki), HTTP 200). The README documents the loop explicitly: *"Make a badge for your README that links to your repo's DeepWiki. **We auto-refresh DeepWikis if their repo has a badge**"* ([raw README](https://raw.githubusercontent.com/CognitionAI/deepwiki/main/README.md), HTTP 200); badge generator live at [deepwiki.com/badge-maker](https://deepwiki.com/badge-maker), HTTP 200. This is the cleanest primary-source instance of "the artifact embeds a link, and embedding the link buys you a better artifact."
- **CodeRabbit** — the output of the product *is* a comment in someone else's pull request, visible to every reviewer on that PR ([coderabbit.ai](https://www.coderabbit.ai/), HTTP 200). This is viral output and CI wedge at once (see §2).
- **Vercel preview deployments** — mechanism stated loudly, never quantified: *"Vercel automatically creates a shareable live Preview URL with every code change so anyone can experience your site"* ([vercel.com/blog/making-live-reviews-a-reality](https://vercel.com/blog/making-live-reviews-a-reality-enhanced-preview-experience), HTTP 200); *"it's easier than ever to collaborate across your organization, by simply sharing a link"* ([commenting on preview deployments](https://vercel.com/blog/introducing-commenting-on-preview-deployments), HTTP 200).
- **shields.io / README badges** — [badges/shields](https://github.com/badges/shields) has **27,201 stars [audited]**. Note the measurement trap: badges are consumed as hotlinked images, so the `shields` npm package shows **43 downloads/month** — **npm download counts do not measure this channel at all.**
- **"Powered by" footers** — [Framer's help doc](https://www.framer.com/help/articles/how-do-i-remove-the-made-in-framer-badge-from-my-website/) (HTTP 200) shows the watermark is also a *conversion lever*: *"The 'Made in Framer' badge will automatically disappear once you connect a custom domain or upgrade your site to a paid subscription."*
- **Docker pulls as a distribution metric** — Docker's own blog: *"8 billion pulls! Yes, that's billion with a B!"* in an average month ([Introducing the Docker Index](https://www.docker.com/blog/introducing-the-docker-index/), HTTP 200). Per-image counts are **audited and machine-readable**: `redis` **11,311,595,604**, `python` **9,257,853,707**, `node` **6,993,873,996** pulls ([hub.docker.com API](https://hub.docker.com/v2/repositories/library/redis/)).

**Evidence:** the *mechanism* is extremely well-evidenced by primary sources; the *magnitude* is essentially unpublished. DeepWiki's MCP-adjacent scale is the closest thing to a real number: **1.4 million repositories indexed and over 20 million queries served** ([ZenML LLMOps database entry on Cognition](https://zenml.io/llmops-database/auto-generated-codebase-documentation-and-intelligence-at-scale), HTTP 200, 2026) — a third-party case-study writeup, so treat as directional. **UNVERIFIED: how much of any product's growth came from a shareable artifact.** Multiple search phrasings for k-factor, viral coefficient, or referral attribution for developer tools surfaced only growth-marketing literature and SEO farms. **No developer tool was found publishing a measured viral coefficient** — if you see one for a dev tool, assume it is fabricated unless it comes with a methodology. **GitHub Marketplace as a channel likewise has no official scale figure:** [GitHub's own docs](https://docs.github.com/en/apps/github-marketplace/github-marketplace-overview/about-github-marketplace-for-apps) say only that it *"connects you to developers who want to extend and improve their GitHub workflows"*, and a [GitHub Community request for install statistics](https://github.com/orgs/community/discussions/65959) sits unanswered. The only Marketplace-as-channel datapoint is CodeRabbit's unaudited *"most installed AI App on both GitHub and GitLab"* (see §2).

## 2. CI / workflow integration as a distribution wedge

**Mechanism:** the tool enters where the work already happens — the pull request — so the first artifact a developer sees is a comment in their own diff, not a signup page or a local install.

**Cases:**

- **CodeRabbit (the strongest case in this whole report).** [Series B blog](https://www.coderabbit.ai/blog/coderabbit-series-b-60-million-quality-gates-for-code-reviews) (HTTP 200): *"installed on 2 million repos, reviewed 13 million pull requests, become the most installed AI App on both GitHub and GitLab"* — **self-reported**. Independent corroboration of the repo scale from a security researcher, one month earlier: *"write access on **1M repositories**"* ([Kudelski Security, Aug 19 2025](https://research.kudelskisecurity.com/2025/08/19/how-we-exploited-coderabbit-from-a-simple-pr-to-rce-and-write-access-on-1m-repositories/), HTTP 200; [HN 687 pts / 227 comments](https://news.ycombinator.com/item?id=44953032) **[audited]**). By Aug 2026: **30 million+ PRs reviewed, 2M+ reviews per week, 17,000+ organizations, revenue up "more than 5x" YoY, $143M Series C at a $1.5B valuation** ([CodeRabbit newsroom](https://www.coderabbit.ai/newsroom), HTTP 200; [Reuters coverage linked from it](https://www.reuters.com/5f374b32b07b/technology/ai-code-review-platform-coderabbit-valued-15-billion-latest-funding-round-2026-08-12/), HTTP 200). Earlier stage, audited by TechCrunch: *"growing 20% a month"*, *">$15 million in ARR"*, "over 8,000 other businesses" ([TechCrunch, Sep 16 2025](https://techcrunch.com/2025/09/16/coderabbit-raises-60m-valuing-the-2-year-old-ai-code-review-startup-at-550m/), HTTP 200 — still the founder's number, unaudited).
  **The channel contrast is the finding:** CodeRabbit's own VS Code extension sits at **189,730 installs** while the PR channel claims **2M repos**. The PR surface beats the IDE surface by roughly an order of magnitude for the same product.
- **Dependabot** — not a product you install but a GitHub App whose PRs land in the same review queue as humans ([github.com/apps/dependabot](https://github.com/apps/dependabot)). Ubiquity measured as complaint volume: *"Turn Dependabot off"* **647 pts / 185 comments [audited]** ([HN](https://news.ycombinator.com/item?id=47094192)). Default-on distribution buys scale and this much backlash.
- **Renovate** — **22,561 stars [audited]** ([renovatebot/renovate](https://github.com/renovatebot/renovate)), ~4× Dependabot Core (**5,777 stars** [audited]). The reason is in the docs: it supports Azure DevOps, Bitbucket Cloud/Server, Gitea, Forgejo, Gerrit, GitLab and more whereas Dependabot is GitHub-only ([docs.renovatebot.com](https://docs.renovatebot.com/)). It also ships via the one-command channel: `renovate` at **279,221 npm downloads/week [audited]**.
- **Snyk** — the same engine reachable from IDE, CLI *and* SCM with a free-forever tier ([snyk.io/plans](https://snyk.io/plans/), HTTP 200: $0 with 5 projects, 100 SAST tests/month). Audited distribution: `snyk` CLI **496,419 npm/week**, VS Code extension **461,645 installs**. ARR **"$300 million"** [self-reported via press] ([TechCrunch, Dec 6 2024](https://techcrunch.com/2024/12/06/snyk-hits-300m-arr-but-isnt-rushing-to-go-public/), HTTP 200).
- **Codecov** — *"Code coverage pull request comments allow you to quickly analyze your PR's coverage and risk **without leaving your workflow**"* ([about.codecov.io](https://about.codecov.io/)); scale self-reported as *"nearly 1.5 million of you"* ([Codecov joining Sentry](https://about.codecov.io/blog/codecov-is-joining-sentry-heres-what-you-need-to-know/), HTTP 200), against **406,844 npm/week [audited]**.

**Evidence:** GitHub Actions Marketplace is a real, large channel — developers used **11.5 billion Actions minutes in public/open-source projects in 2025, up 35% YoY**, and the platform runs **71 million jobs per day** ([GitHub blog, Dec 11 2025](https://github.blog/news-insights/product-news/lets-talk-about-github-actions/), HTTP 200). It is also crowded, per peer review: the Marketplace is *"expanding by approximately 41% annually"*, but of 6,983 CI Actions linked to 3,869 providers, *"approximately 65% of new CI Actions replicate existing capabilities, typically within six months"*, with first-movers capturing most downstream forks ([arXiv:2507.23168 / JSS 2025](https://arxiv.org/abs/2507.23168), HTTP 200). Scale of the venue: **8,318 automated production tools (440 Apps, 7,878 Actions) across 32 categories** ([arXiv:2407.05519](https://arxiv.org/abs/2407.05519), HTTP 200, 2024 — the Apps count is small and dated).

**Honest caveat:** the *causal* claim "PR comments drove adoption" is asserted by vendors and never measured in public. **UNVERIFIED: any CodeRabbit-published referral, attribution, or k-factor figure.** What is verifiable is the channel/IDE install-count asymmetry above.

## 3. One-command install / zero-friction onboarding

**Mechanism:** reduce the distance from "heard of it" to "it ran on my machine" to one line.

**Cases:**

- **`npx` / `create-*`.** The primary evidence for the friction argument is the registry maintainer's own words: *"Have you ever run into a situation where you want to try some CLI tool, but it's annoying to have to install a global just to run it once?"* and, from the maintainer side, *"I can just put `$ npx my-tool` into the README.md instructions, **instead of trying to get people over the hurdle of actually installing it**"* ([npm blog, 2017](https://blog.npmjs.org/post/162869356040/introducing-npx-an-npm-package-runner.html), HTTP 200). Audited volume: `@angular/cli` **4,379,524/week**, `create-next-app` **294,722/week**, plus the PostHog wizard's `npx @posthog/wizard` (see §4).
- **`brew install`.** Homebrew's public analytics API is the cleanest audited installer-side data available **[all audited]**: `gh` **170,720 / 725,628 / 2,927,560** (30d/90d/365d), `uv` **129,202 / 522,790 / 1,863,315**, `node` **116,104 / 671,438 / 3,078,156**, `ripgrep` **34,501 / 212,870 / 711,871**, `docker` **21,466 / 144,159 / 753,486** ([formulae.brew.sh API](https://formulae.brew.sh/api/formula/gh.json)). One package manager is a millions-per-year channel for a CLI.
- **Single static binary.** Astral ships the principle under a heading called *"Optimized for adoption"*: *"uv ships as a **single static binary**... no direct Python dependency, so you can install it separately"*, promising `zero configuration` ([astral.sh/blog/uv](https://astral.sh/blog/uv), HTTP 200), installed via one line on each OS ([uv docs](https://docs.astral.sh/uv/getting-started/installation/)).
- **VS Code Marketplace (the biggest single channel found).** Microsoft's dated first-party source: *"**50 million developers** are actively using Visual Studio and Visual Studio Code each month"* and *"**Over 100,000 extensions** in the VS Code Marketplace"* ([Microsoft for Developers, May 15 2025](https://developer.microsoft.com/blog/celebrating-50-million-developers-the-journey-of-visual-studio-and-visual-studio-code/), HTTP 200). Per-extension installs, pulled live from the Marketplace API **[audited]**: `ms-python.python` **237,828,381**; `esbenp.prettier-vscode` **71,748,496**; `GitHub.copilot` **74,618,185**; `dbaeumer.vscode-eslint` **52,916,833**; `eamodio.gitlens` **52,857,975**; `saoudrizwan.claude-dev` (Cline) **5,405,401**; `Continue.continue` **4,198,457**.

**Evidence:** the direction of the friction argument is documented (npm's post, uv's design), and the size of the Marketplace channel is documented precisely. Quantified conversion impact is **not**: the best vendor-published number is DevCycle, who rebuilt onboarding around an editor-native MCP flow so developers *"start inside their editor with our SDK — **not a detour through example apps or sandboxes**"*, reporting *"**~3× more users reach SDK install** versus our previous flow"* and diagnosing the old flow as *"**most users skipped the flow altogether**"* ([blog.devcycle.com](https://blog.devcycle.com/we-rebuilt-our-onboarding-around-mcp-the-result-3x-sdk-installs/), HTTP 200, Oct 2025) — **self-reported, no methodology published**. **UNVERIFIED: any neutral/audited study linking install-step count to conversion.** The 50M figure also conflates Visual Studio with VS Code, and no Marketplace-specific MAU was found.

## 4. Immediately useful output ("aha in 60 seconds")

**Mechanism:** the user gets a completed, valuable output quickly enough to feel it before they churn.

**Cases:**

- **PostHog's onboarding wizard — the best-documented activation numbers in developer tooling.** From [We used context engineering to 5x conversion and 2x activation](https://posthog.com/newsletter/context-engineering) (HTTP 200, Jun 2026), verbatim: *"**5x paid conversion**: 14.2% of wizard users convert to paid usage vs 2.6%"*; *"**2x faster activation**: first event in 1.9 hours vs 3.8, with 94% activating within one hour vs 67%"*; *"80% larger MRR in the first paying month"*; and the time-to-value claim itself: *"today's wizard completes **two hours of work in just 8 minutes**"*. It is delivered as one command (`npx @posthog/wizard`) — the output is immediate because the *install step was deleted*. **All self-reported**, no methodology or sample size, and the cross-check is modest: `@posthog/wizard` shows **25,668 npm downloads in the last month [audited]**. Also useful because PostHog defines activation operationally as **one completed output per product** ("Events ingested, 1 insight created, 1 dashboard created…"), not a login ([how we built our onboarding email flow](https://posthog.com/blog/how-we-built-email-onboarding), HTTP 200).
- **Bruno** — 78 releases in a year and an explicit "remove friction on onboarding/migration from Postman" focus ([blog.usebruno.com](https://blog.usebruno.com/bruno-2025-from-idea-to-daily-driver), HTTP 200); see §8 for its numbers.
- **Amplitude benchmarks** — real numbers, but not dev-tool-specific: *"In just 14 days, as many as 91% of your new users may drop off"*; p90 Day-1 activation *"around 21%"*; *"More than 98% of users churn within two weeks if they haven't experienced value"* ([amplitude.com/blog/time-to-value-drives-user-retention](https://amplitude.com/blog/time-to-value-drives-user-retention), HTTP 200). **Caveat:** Amplitude's per-industry drill-down renders client-side, so the *technology* slice is not publicly extractable — the HTML returns placeholder `0 %`.

**The most directly transferable artifact in this report is PostHog's operational definition of activation, plus one onboarding design choice.** Activation is defined as **one completed output per product** — *"Product analytics: Events ingested, 1 insight created, 1 dashboard created. Session replay: 5 recordings viewed. Feature flags: 1 feature flag created…"* — not a login, not a signup ([how we built our onboarding email flow, with actual performance data](https://posthog.com/blog/how-we-built-email-onboarding), HTTP 200). Iterated funnel, self-reported and published per version: v1 open 56% / CTR 7.4% / conversion 3%; v5 52% / 4% / 6%; v6 50% / 2.4% / 3.5%; v7 52% / 3.1% / 2.2% — i.e. **the funnel was measured and re-measured, not asserted**. The design choice worth stealing: *"we added a one hour delay so that users can get data to work with first"* — the email is deliberately held back until the product has produced something. For Fieldguide that maps to: don't email, upsell, or ask for anything until the graph and the first guided tour exist on screen.

**Evidence:** this mechanism has the best vendor-published funnel math of the eight, and it is unaudited in every case. **No independent, audited, dev-tool-specific activation benchmark was found to exist in public.** The "TTFV benchmark" search genre is contaminated: results were almost entirely content-marketing pages recycling numbers that trace to no dataset — do not cite them.

## 5. Network effects / community / open-source-first

**Mechanism:** an OSS core or a community creates distribution and goodwill, which is supposed to convert commercially.

**Cases:**

- **Sentry (cleanest single statement of OSS → revenue).** *"we now support over **100,000 organizations** and we passed **$100 million in ARR** last year"* ([blog.sentry.io, May 2024](https://blog.sentry.io/building-for-the-fortune-500-000/), HTTP 200) — **self-reported**; **44,823 stars [audited]** ([getsentry/sentry](https://github.com/getsentry/sentry)).
- **Grafana (clearest trajectory, two dated points).** **$400M ARR and 7,000+ organizations** (Sep 30 2025, [press release](https://grafana.com/press/2025/09/30/grafana-labs-surpasses-400m-arr-and-7000-customers-gains-new-investors-to-accelerate-global-expansion/)) → **$600M ARR and 10,000 customers** (Aug 26 2026, [press release](https://grafana.com/press/2026/08/26/grafana-labs-crosses-10000-customer-milestone-as-ai-adoption-accelerates-growth-across-the-platform/), HTTP 200). **76,853 stars [audited]**. Both self-reported.
- **Supabase.** **110,592 stars [audited]**; *"Nearly **10 million developers** build on Supabase today, more than doubling since our last fundraising announcement eight months ago"*, database launches **+600% YoY**, and *"more than 60% of new databases are launched by some sort of AI tool"* ([supabase.com/blog/supabase-series-f](https://supabase.com/blog/supabase-series-f), HTTP 200 — published the day of a $500M round; directional, not audited). TechCrunch's earlier coverage called its *"biggest asset... the community of"* developers around it ([TechCrunch, Apr 2025](https://techcrunch.com/2025/04/22/vibe-coding-helps-supabase-nab-200m-at-2b-valuation-just-seven-months-after-its-last-raise/), HTTP 200).
- **PostHog (the "build in public" case).** **39,897 stars [audited]**; *"Over **500,000 teams** have signed up"* ([handbook](https://posthog.com/handbook/how-we-get-users), HTTP 200); *"On Pace for **$100 Million ARR**"* ([Stripe customer story](https://stripe.com/customers/posthog), HTTP 200). PostHog ships its handbook *as source code on GitHub* — the mechanism and the artifact are the same thing.
- **Counter-case — Sourcegraph.** Large OSS community did **not** convert: it went proprietary without announcement ([HN 444 pts](https://news.ycombinator.com/item?id=36584656)), then private ([ex-employee post](https://eric-fritz.com/articles/sourcegraph-went-dark/), [HN 424 pts](https://news.ycombinator.com/item?id=41296481)), then deleted Cody Free and Pro on **July 23, 2025** ([primary post](https://sourcegraph.com/blog/changes-to-cody-free-pro-and-enterprise-starter-plans) — **403 to every client; verified via [Wayback](https://web.archive.org/web/20260619065251/https://sourcegraph.com/blog/changes-to-cody-free-pro-and-enterprise-starter-plans)**), offering **$10 / $40** in Amp credits as migration.
- **Aider and Continue.dev** — **49,114** and **35,987 stars [audited]** respectively, with **no commercial numbers published at all**. The absence is the finding.

**Evidence:** the pattern is a *shape*, not a conversion rate: every company with large published ARR has a 35k–110k-star OSS core, but the two highest star-to-commercial ratios publish nothing. **Stars do not predict revenue.** **UNVERIFIED: any credible published OSS→paid conversion rate.** The widely repeated "1–3%" (and one consultancy's "0.5–3%", citing an unlinked "OpenView Partners") has no primary source we could locate — do not quote it as a benchmark. The practical read for a local-first tool: the OSS layer buys **distribution and goodwill, not conversion**, and revoking it destroys the asset rather than monetizing it.

## 6. AI-era specifics: MCP as a distribution channel

**Mechanism:** publishing a Model Context Protocol server puts your product inside the AI assistant the developer already has open, instead of asking them to visit your app.

**Cases:**

- **Protocol substrate [all audited].** `modelcontextprotocol/servers` — **90,546 stars**, 11.7k forks; `@modelcontextprotocol/sdk` — **40,301,962 downloads in the week 2026-09-15→21**; `@modelcontextprotocol/server-filesystem` — **497,862** that week ([npm API](https://api.npmjs.org/downloads/point/last-week/@modelcontextprotocol/sdk)). 40M/week means MCP is default infrastructure, not an experiment. Origin: Anthropic open-sourced MCP **Nov 25, 2024**, naming **Block** and **Apollo** as early adopters ([anthropic.com/news/model-context-protocol](https://www.anthropic.com/news/model-context-protocol), HTTP 200).
- **OpenAI adopting MCP** is what made it a channel: first-class MCP support across stdio, Streamable HTTP and SSE, plus hosted MCP server tools where *"OpenAI's Responses API call[s] a publicly reachable MCP server on the model's behalf"* ([OpenAI agents SDK docs](https://github.com/openai/openai-agents-python/blob/main/docs/mcp.md); [OpenAI MCP connectors guide](https://developers.openai.com/api/docs/guides/tools-connectors-mcp)). The original March 2025 announcement post was unfetchable (403, no Wayback snapshot) — **UNVERIFIED at that URL**; the docs are the primary substitute.
- **Block** — MCP rolled to **12,000 employees across 15 job functions in eight weeks**, **60+ internal MCP servers in week one, "today, we're over 100"**, and **75% of engineers saving 8–10 hours/week** within a month ([The New Stack, Oct 2025](https://thenewstack.io/how-block-got-12000-employees-using-ai-agents-in-two-months/), HTTP 200; [All Things Open](https://allthingsopen.org/articles/block-scaled-mcp-12000-employees-15-job-functions)). Journalists' transcription of a conference talk — **no first-party Block post found**. Transferable tactics: pre-bundled servers by default, SSO instead of API keys, and a public "here's what I built" channel that *"became one of the best organic drivers of adoption."*
- **Smartsheet** — **4,000+ early adopters in the first few days** and **1.74 million total actions since launch**; **48% of actions create/update work rather than read it** ([Smartsheet newsroom](https://www.smartsheet.com/content-center/news/smartsheet-mcp-server-achieves-exceptional-customer-adoption-first-week-4000), HTTP 200; wire syndications returned 403). **Self-reported and timed to launch** — it measures usage, not revenue or retention.
- **DevCycle** — the closest thing to an attribution claim: rebuilding onboarding around MCP produced *"~3× more users reach SDK install"* (see §3). **Self-reported.**
- **GitHub MCP Registry (Sep 16 2025)** — GitHub states the problem in purely distributional terms: *"MCP servers are scattered across numerous registries, random repositories, and buried in community threads... discovery is slow and full of friction"* and *"**With GitHub already home to most MCP servers**, the MCP registry makes them dramatically easier to discover"* ([GitHub changelog](https://github.blog/changelog/2025-09-16-github-mcp-registry-the-fastest-way-to-discover-ai-tools), HTTP 200). A registry built by GitHub *and* consumed by Copilot is the strongest structural signal that shipping an MCP server is a distribution act. Institutionalization: MCP was donated to the **Agentic AI Foundation under the Linux Foundation** ([GitHub blog](https://github.blog/open-source/maintainers/mcp-joins-the-linux-foundation-what-this-means-for-developers-building-the-next-era-of-ai-tools-and-agents/), HTTP 200).
- **DeepWiki did ship an MCP server — and it did not visibly matter.** Cognition shipped the official DeepWiki MCP server on **May 22, 2025**, with `ask_question`, `read_wiki_contents`, `read_wiki_structure`, *"completely free with no login or auth"*, and notes that **"OpenAI shared examples of using the DeepWiki MCP server with their API"** ([cognition.com/blog/deepwiki-mcp-server](https://cognition.com/blog/deepwiki-mcp-server), HTTP 200) — but **published no adoption numbers for it**. Best available proxy **[audited]**: the third-party wrapper `deepwiki-mcp` at **1,029 weekly npm downloads** — about **0.003%** of the official SDK's 40.3M/week. Real, free, and unmeasured.

**Evidence:** the protocol layer is the hardest evidence in this document (live APIs). The company layer is weaker: Block is a talk transcription, Smartsheet is a launch-timed release, DeepWiki published nothing. **UNVERIFIED: any vendor blog that quantitatively attributes growth or revenue to being an MCP server.** Anthropic publishes no MCP adoption statistics, so "MCP as a channel" rests on third-party platform behavior rather than protocol-owner disclosure. Honest read: **a cheap, now-expected distribution surface with strong ecosystem proof and almost no published proof of conversion** — worth shipping into, not worth forecasting revenue from.

## 7. Counter-evidence: what does NOT drive adoption

**Sourcegraph is the best-documented failure, and it is Fieldguide's exact play.** Its public handbook FAQ states the funnel verbatim: *"The app is a critical part of our effort to become more product led because it gets individual devs up an running with a Cody-supported Sourcegraph instance quickly, easily, and for free"*, with the journey *"A dev finds out about Sourcegraph → They use Sourcegraph App locally on their code → They upgrade to a Cloud trial"* ([handbook app-faq.md](https://raw.githubusercontent.com/sourcegraph/handbook/main/content/departments/engineering/teams/app/app-faq.md), HTTP 200). Its declared metrics were only **"Number of downloads", "Number of trial starts", "CTA activity"** ([analytics.md](https://raw.githubusercontent.com/sourcegraph/handbook/main/content/departments/engineering/teams/app/analytics.md)) — **no CI or PR surface anywhere in the metric set.** The launch got **1 point on HN** ([item 35399947](https://news.ycombinator.com/item?id=35399947)). The app was folded into "the Cody app", repositioned as an IDE backend, then died with Cody Free. The end state of that trajectory: **Amp spun out of Sourcegraph in Dec 2025** ([HN 90 pts, 2025-12-02 **[audited]**](https://news.ycombinator.com/item?id=46124649)). Verified dates for the three HN threads in this sequence: **2023-07-04** (444 pts), **2024-08-20** (424 pts), **2025-12-02** (90 pts) — a four-year arc from OSS darling to spinoff, with no conversion step anywhere in it.

Other documented failures and their stated reasons:

- **Atom** — GitHub's own words: *"Atom has not had significant feature development for the past several years"*; *"As new cloud-based tools have emerged and evolved over the years, Atom community involvement has declined significantly"*; *"we've decided to retire Atom in order to further our commitment to bringing fast and reliable software development to **the cloud**"* ([Sunsetting Atom, Jun 2022](https://github.blog/news-insights/product-news/sunsetting-atom/), HTTP 200; [HN 1320 pts / 853 comments](https://news.ycombinator.com/item?id=31668426) **[audited]**). A desktop editor was retired toward cloud — the opposite of a desktop-only bet.
- **Forced behaviour change and forced accounts are the real churn drivers.** *"Tell HN: Postman update removes all your stuff if you refuse to create account"* — **365 points [audited]** ([HN](https://news.ycombinator.com/item?id=37792690)); the top-voted remedy in-thread was a competing desktop app (*"I have found Bruno... to be a decent basic alternative"*). Insomnia hit the same wall first. **Bruno's launch thread scored 1538 points** — it grew out of a competitor's forced-login failure, not out of a marketplace.
- **Install friction, from users rather than vendors:** *"Distributing Mac software is increasing my cortisol levels"* — **398 pts / 286 comments [audited]**; *"Between quarantine, code signing, and notarizing (which requires $99 a year), it's just not worth it"* ([HN](https://news.ycombinator.com/item?id=48075366)). Electron's own docs confirm the constraint: *"Both Windows and macOS prevent users from running unsigned applications... users need to go through multiple advanced and manual steps"* ([code signing](https://www.electronjs.org/docs/latest/tutorial/code-signing), HTTP 200).
- **A desktop tool cannot even count its own failure.** Beekeeper Studio: *"we don't use any tracking software in our app, we don't have exact download or active user numbers"*; total downloads *"probably somewhere in the region of 50,000 - 100,000, it's hard to tell"* ([Q3 2020 by the numbers](https://www.beekeeperstudio.io/blog/q3-by-the-numbers), HTTP 200).
- **Free→paid conversion, the only dataset with a disclosed sample:** ChartMogul + ProductLed's **200-product** B2B survey — free trial **57%** conversion vs freemium **26%**; **median free-to-paid 8%**; trials requiring a card convert at **30%**, *"more than 5x"* those that do not ([SaaS Conversion Report, Feb 2026](https://chartmogul.com/reports/saas-conversion-report/), HTTP 200). **Not dev-tool-specific, and it is a survey of self-reported vendor data.**
- Also verified: Google Cloud IoT Core's sunset blog URL is a **404** (cite press coverage, not Google Graveyard); Arctype (a desktop SQL client) reached EOL in Dec 2022 with **no primary announcement** we could find ([HN 27 pts](https://news.ycombinator.com/item?id=33114111)).

**Evidence:** the recurring failure modes are **no integration point** (a destination you must remember to open), **required behaviour change** (forced accounts), **install/setup friction**, and **unclear value**. **UNVERIFIED: any measured free→paid dataset specific to developer tools, and any credible measured dataset for "a destination app you must remember to open"** — the best on-record evidence is HN comment volume plus vendors conceding they cannot measure desktop usage at all.

## 8. Desktop apps specifically

**The key structural concession: no CI hook and no PR surface.** A standalone binary cannot post a comment into someone's pull request, cannot be defaulted-on for an org, and cannot be measured the way a server-side app can. The evidence for what that costs:

- **The channel you give up is enormous and audited.** VS Code Marketplace installs (live API): Python extension **237,828,381**, Copilot **74,618,185**, GitLens **52,857,975** — versus **189,730** for CodeRabbit's IDE extension *and* CodeRabbit's own claim of **2M repos** via the PR surface. Sourcegraph's answer, after its desktop app failed, was the Cody **IDE extension**, which outlived the app.
- **Install friction is structural, not fixable by better UX:** code signing, macOS quarantine/notarization, the $99/yr Apple fee, unsigned-binary warnings (Electron docs + the 398-point HN thread above). **UNVERIFIED: any published link between bundle size (Tauri's "as little as 600KB") and dev-tool adoption.**
- **Desktop tools that did spread did so through a wedge, not a store listing:**
  - **Bruno** — the best-documented desktop growth trail **[self-reported but specific]**: monthly active users **~250k (Jan 2025) → 600k+ (Dec 2025)**, **250k new users in a single month at peak**, stars **26k → 40k** in the same year, 78 releases, team 6 → 23 people ([Bruno 2025 recap](https://blog.usebruno.com/bruno-2025-from-idea-to-daily-driver), HTTP 200); **47,110 stars [audited]** now; HN launch **1538 pts / 400 comments [audited]**. Its wedge: Postman's forced-account failure, offline-first, Git-native, plus an IDE extension and a CLI for automation.
  - **DBeaver** — **51,832 stars [audited]**; free CE plus published paid tiers from **$113/yr** ([dbeaver.com/edition](https://dbeaver.com/edition/)).
  - **Beekeeper Studio** — **23,641 stars [audited]**; **100,000+ web visits and 10,000+ app downloads** in the Apr–May 2020 launch window, later *"monthly unique visitors and app downloads have grown 4x"* ([Q3 2020](https://www.beekeeperstudio.io/blog/q3-by-the-numbers), [2.0 retrospective](https://www.beekeeperstudio.io/blog/release-2.0), both HTTP 200). On why free alone failed: *"maintaining such a large project without any revenue became impossible, and so I made the decision to create a commercial fork"* ([open-source.md](https://raw.githubusercontent.com/beekeeper-studio/beekeeper-studio/master/docs/support/open-source.md)).
  - **Obsidian** — the closest analogue to Fieldguide's shape (local-first desktop, optional paid sync). *"People in over **10,000 organizations** use Obsidian for work"*; the commercial licence became **optional** in Feb 2025, monetizing via Sync/Publish instead ([free for work](https://obsidian.md/blog/free-for-work/), HTTP 200); *"Obsidian plugins have passed **120 million total downloads**"* with *"more than 4,000 plugins and themes"* ([future of plugins](https://obsidian.md/blog/future-of-plugins/), HTTP 200) — the community plugin ecosystem is the growth engine. Privacy is load-bearing: *"our apps do not collect telemetry data."*
  - **Zed** — **90,716 stars [audited]**; 1.0 in Apr 2026 with *"hundreds of thousands of developers now rely on Zed"* and **$32M Series B led by Sequoia** ([zed.dev/blog/zed-1-0](https://zed.dev/blog/zed-1-0), [sequoia backs zed](https://zed.dev/blog/sequoia-backs-zed)).
  - **TablePlus** — sustained a native commercial business largely on HN attention (**562 pts / 190 comments [audited]**).

**A correction to the brief:** **DBngin is *not* discontinued.** The live site ([dbngin.com](https://dbngin.com/), HTTP 200) markets *"The easiest way to get started with PostgreSQL, MySQL, MariaDB, Redis & more"* with **both macOS and Windows downloads**, and its [release log](https://dbngin.com/blog) lists Mac **Build 92 released 4 September 2026** (MySQL 9.7.2). Its GitHub repo (1,237 stars) is not archived. An earlier `HEAD` request to the homepage returned 404 on this network, which is why the first draft flagged the URL as uncertain; a direct `GET` resolves 200, and the site is live. **UNVERIFIED: any discontinuation announcement — none appears to exist.** Do not cite DBngin as a sunset. Note also that its publisher is TablePlus, which supports the wider point in this section: a small desktop-tool family can sustain itself for years without a PR surface, a marketplace, or any published user count.

**Evidence:** desktop-only tools *can* spread — Bruno, DBeaver, Obsidian, Zed and Beekeeper all did — but every one of them spread through a **wedge** (a competitor's forced behaviour change, an IDE extension, a plugin ecosystem, a launch thread), **not through a store or a CI surface.** Nobody found a desktop dev tool that spread by being a place you remember to visit.

## Ranked hooks for Fieldguide

Ranking = **evidence strength × structural fit for a local-first desktop knowledge-graph tool.** The honest framing up front: Fieldguide's product is a *destination app*, and the strongest evidence in this document belongs to mechanisms that are anti-destination. So the ranking deliberately favors mechanisms Fieldguide can actually reach, and flags the two it structurally cannot.

**1. Immediately useful output — "aha in 60 seconds" (strong evidence, perfect fit).**
The best-documented activation numbers in dev tooling come from exactly Fieldguide's problem: pointing a tool at an unfamiliar codebase. PostHog's wizard: **14.2% vs 2.6% paid conversion**, **first event in 1.9h vs 3.8h**, **94% vs 67% activating within an hour**, and **"two hours of work in just 8 minutes"** ([source](https://posthog.com/newsletter/context-engineering)). Fieldguide's equivalent is one command / one "open this folder" that produces a **rendered graph and a guided tour of a repo the user did not write**, before any account, config, or LLM key. Highest-leverage, cheapest, and fully within its control. Weakness: every supporting number is self-reported, and the audited proxy is modest.

**2. Shareable artifacts / viral output (strongest *mechanism* evidence, strong fit).**
DeepWiki's badge-and-auto-refresh loop is the cleanest primary-source case in the report, and it maps onto Fieldguide with almost no translation: a **publishable, linkable artifact per repository** — an architecture graph, a layer view, a guided tour — that carries a back-link and gets refreshed when the link is embedded. The artifact must be **public and URL-addressable**; a local-only graph has zero viral surface. This is the single highest-value change in product *shape* (not just marketing). Weakness: nobody publishes the magnitude, so choose it for its mechanics, not for a modeled k-factor.

**3. MCP server as a distribution surface (strong ecosystem evidence, strong fit).**
**40.3M npm downloads/week** for the official SDK **[audited]**, a **GitHub-run MCP Registry** (Sep 2025) built on the premise that GitHub is *"already home to most MCP servers"*, and adoption into ChatGPT/Claude/Cursor. For Fieldguide this is the natural way to *escape the destination-app trap*: expose the knowledge graph as an MCP server so `ask_question`-style queries work inside the editor or agent the developer already uses, with the graph as the grounded context. Cheapest distribution move available to a desktop app — an MCP endpoint needs no CI surface. Weakness: **no vendor has published revenue or retention attributable to being an MCP server**; DeepWiki shipped one and published nothing. Ship it; don't forecast from it.

**4. One-command install / zero friction (strong channel evidence, medium fit).**
The channel is real and audited: VS Code Marketplace at **237.8M installs** for a top extension and **100,000+ extensions**, `brew` at millions of installs/year, `npx` as a maintainer-controlled one-liner ([npm blog](https://blog.npmjs.org/post/162869356040/introducing-npx-an-npm-package-runner.html), HTTP 200). For a Windows Electron app the honest version is: **a signed single installer that runs immediately on a clone, plus a VS Code extension** as the low-friction front door (an extension carries the graph/tour into the editor; the desktop app is the deep-work surface). This is also where Fieldguide is currently weakest — unsigned Electron apps trigger SmartScreen, and the **398-point HN thread** plus Electron's own docs show install friction is the tax desktop pays.

**5. CI / PR workflow integration (strongest evidence in the report — and structurally unavailable).**
CodeRabbit is by far the best case in this document: **2M repos / 13M PRs** ([self-reported](https://www.coderabbit.ai/blog/coderabbit-series-b-60-million-quality-gates-for-code-reviews)) independently echoed as **1M repos**, **30M+ PRs and 2M reviews/week** by Aug 2026, revenue **5x YoY**, **$143M at $1.5B** — versus **189,730** installs for its own IDE extension. The PR surface beat the IDE surface ~10×. **Fieldguide cannot use this:** it has no server, no PR comment, and nothing to default-on for an org. Its only adjacent move is read-only: consume PR/commit history as *input* to the graph (which repos a newcomer's team actually touches).

**6. Network effects / community / open-source-first (medium evidence, medium fit, high risk if done wrong).**
Every large published ARR in this set has a 35k–110k-star OSS core (Grafana $400M→$600M ARR; Sentry **100,000 orgs / $100M ARR**; Supabase ~10M developers), and Obsidian's **120M plugin downloads** show a plugin ecosystem is a genuine growth engine for a desktop knowledge tool. But Sourcegraph proved the direction is asymmetric: revoking OSS/free tiers destroys the asset rather than monetizing it (**444-pt** and **424-pt** HN threads), and Aider (49k stars) and Continue (36k stars) publish **no commercial numbers at all**. **Stars do not predict revenue.** For Fieldguide: consider an open OSS core plus a plugin/extension surface, and treat community as *distribution and goodwill*, not as a conversion funnel.

**7. Desktop-only breadth (weak evidence; a constraint, not a hook).**
The desktop tools that spread each had a wedge, not a store listing — Bruno grew out of Postman's forced accounts (**1538-pt launch**, MAU **250k→600k+** in 2025), Obsidian out of local-first privacy plus plugins, Zed out of performance and a strong dev following. Fieldguide is the same shape, so this is a legitimate *category*, not a growth story to copy. Note the ceiling honestly: Beekeeper Studio had to admit *"we don't have exact download or active user numbers"*, and Sourcegraph's local app benchmarked its success purely on **downloads and trial starts** and got **1 HN point**.

**Where Fieldguide structurally CANNOT use a mechanism:** no PR-comment surface, no CI loop, no default-on org distribution, no server-side artifact to auto-publish for every repo in the world (DeepWiki/CodeRabbit's core loop), and no package-manager-native one-liner in the way `npx`/`brew`/a marketplace extension is. Any "hook" that assumes Fieldguide generates content *inside someone else's pull request* or *inside a hosted service* should be discarded rather than adapted.

**The single recommended hook, stated plainly:** make Fieldguide's **output the artifact** — one repository in, one public linkable interactive graph/tour out, produced in minutes with no account, published with a back-link, and simultaneously queryable through an MCP server so the value lands inside the editor the developer already has open. That combines the two best-evidenced and best-fitting mechanisms (§4 and §1) with the cheapest distribution surface available to a desktop app (§6) — and it directly attacks the "too single-feature" complaint by making the product's *output*, not its feature list, the thing other people see.

## Weak evidence

- **No k-factor, viral coefficient, or referral attribution exists publicly for any developer tool.** Multiple phrasings returned only growth-marketing literature and SEO farms. The shareable-artifact mechanism is real, universal, and **unmeasured**.
- **No official GitHub Marketplace scale figure.** GitHub's docs give no app/install/reach number; a [community request](https://github.com/orgs/community/discussions/65959) for install statistics is unanswered. CodeRabbit's *"most installed AI App"* is unaudited.
- **No neutral or audited study linking install-step count to conversion rate.** Only npm's own `npx` rationale (a maintainer's statement of intent) and DevCycle's self-reported "~3×".
- **No dev-tool-specific activation benchmark.** Amplitude's TTFV figures are cross-industry and its technology slice is not extractable from the public web (values render client-side).
- **No measured free→paid conversion dataset for developer tools**, and none for desktop dev tools. The only dataset with a disclosed sample (ChartMogul/ProductLed, 200 B2B products, median 8%) is not dev-tool-specific and is a survey of vendor self-reports.
- **The OSS→paid "1–3%" figure has no primary source.** One consultancy states 0.5–3% citing an unlinked "OpenView Partners"; Elastic's "~1%" is second-hand. Treat as folklore.
- **No vendor blog quantitatively attributes growth or revenue to being an MCP server.** Smartsheet's 4,000 users / 1.74M actions is launch-timed usage, not revenue or retention. DeepWiki shipped a real MCP server and published zero numbers (third-party wrapper: **1,029 weekly npm downloads**).
- **DeepWiki's own growth attribution is partial.** Its badge/auto-refresh loop is documented in its README, but Cognition published no referral or traffic numbers; the 1.4M-repo / 20M-query figures come from a third-party case-study database, and its launch-day HN thread was only **231 points**.
- **Dead or unfetchable (dropped, not cited as if live):** Sourcegraph's Cody pricing-change post and OpenAI's March 2025 MCP announcement (both **403 to every client, no Wayback snapshot** — substitutes used and labelled); `dependabot.com` acquisition post (dead; cited via the surviving [HN thread](https://news.ycombinator.com/item?id=19989631)); Google Cloud IoT Core sunset blog (**404**); Arctype's EOL announcement (no primary source found); Heroku free-tier sunset (no official post).
- **Premise correction:** **DBngin is not discontinued** — Build 92 shipped 4 September 2026 and its repo is not archived. There is no sunset announcement to cite.
- **No link found between Tauri/Electron bundle size and dev-tool adoption**; Tauri's 600KB claim is a size claim, self-reported, with no adoption evidence attached.
- **Unaudited-by-nature:** all ARR, "users", "organizations", and growth-percentage claims in §5 and §6 are vendor self-reports, many published alongside fundraising rounds (Supabase's and CodeRabbit's especially). The audited layer throughout is: GitHub stars, npm weekly downloads, Homebrew installs, VS Code Marketplace install counts, Docker Hub pulls, HN points/comments, arXiv/JSS peer review, and wire-service funding reports.
- **Time-sensitivity of the audited numbers.** Every live count here (stars, npm/week, Marketplace installs, Homebrew installs, Docker pulls, HN points) is a **point-in-time reading taken in late September 2026** and moves daily — the same extension measured minutes apart differed by tens of thousands of installs.
